# tv-source

TVBox 内置源清单（远程）。改这里 → 推到 GitHub → 手机上点一次「刷新内置源」，App 里的内置清单就整体换掉。

- 远程仓库（主）：<https://github.com/sukai616/tv-source>（**App 实际拉取源是 GitHub raw**）
- **只有 GitHub**；Gitee raw 曾返回 **451**，现已弃用，不再推送或作为备份。
- 清单地址（App 里已内置，也可手动填）：<https://gh-proxy.com/https://raw.githubusercontent.com/sukai616/tv-source/master/builtin.json>
  - 直连备用：<https://raw.githubusercontent.com/sukai616/tv-source/master/builtin.json>
  - 前缀备用：<https://ghfast.top/https://raw.githubusercontent.com/sukai616/tv-source/master/builtin.json>
  （三条 2026-09-29 实测均 200，内容一致；直连在国内不稳，所以 App 内置默认带 gh-proxy 前缀）

## 怎么用

1. App 里：**设置 → 内置源 → 清单地址**。装好就默认是本仓库这条地址（后面标着「内置」），不用手填；想换别的清单才改。
2. **刷新内置源**：拉取本仓库的 `builtin.json`，覆盖 App 内置的点播 / 直播清单（会提示「刷新完成：点播 x 条、直播 y 条」）。
3. 之后**内置点播源 / 内置直播源**两行里列出的，就是这份清单里的条目；带 `recommended` 的排在最上面，
   名字前有「推荐 · 」，备注写在名字后的括号里。选中即切换当前配置地址。

**直播跟随点播**：设置里有一行开关（默认开启）。开启时换点播会顺带换直播地址，因为单仓 JSON 一般
sites 与 lives 在同一份配置里。**一旦你手动选过一条直播源（直播历史 / 内置直播源 / 配置地址弹窗里填的），
这个开关会自动变成「关闭」**，之后换点播不会再改你选的直播源——除非你自己再打开它。

App 侧行为要记住两点：

- 清单是**权威来源**：在 App 里删掉一条内置源只删本地，下次刷新会按清单回来。
- 清单格式不对或里面没有可用条目时，刷新**只提示、不动**本地清单。

## 每次改完怎么推上去

```bash
cd tv-source
# 用任意编辑器改 builtin.json
git add builtin.json
git commit -m "更新内置源清单"
git push github master    # 主仓库：App 实际拉取源，必须推
```

GitHub 的 HTTPS 推送走本机钥匙串令牌（`github.com` / 账号 `sukai616`），不会再问密码；

推完在浏览器打开加速前缀地址或直连 raw 地址，能看到新的 JSON 原文就算成功（能看到内容 = 仓库是公开的，App 才拉得到）。
**注意**：GitHub raw 也有几分钟的 CDN 缓存，推完立刻验证可能还是旧内容，等一下再试。

## 推送前自检（脚本）

`scripts/check_sources.py`，只用 Python 标准库，不用装依赖：

```bash
python3 scripts/check_sources.py                        # 只做静态检查：JSON 合法性、字段/URL 格式、地址重复、backup 规则
python3 scripts/check_sources.py --ipv6                 # 只做 IPv6 体检：本机到底有没有 IPv6 出口
python3 scripts/check_sources.py --sources              # 再看清单里每个地址抓不抓得到
python3 scripts/check_sources.py --live                 # 抓直播源 → 解析频道 → 抽测频道真的能不能播（自动带 IPv6 体检）
python3 scripts/check_sources.py --live --sample 20     # 旧：快速抽测（每源 20 条线路 / 20 个频道名）
python3 scripts/check_sources.py --live --full --phone --json-out /tmp/live-full.json
                                                        # 新：贴近手机 + 全量（周维护用，可能跑很久）
python3 scripts/check_sources.py --live --git f2f4b5a   # 顺手把某个提交里的旧清单也测一遍，做新旧对比
```

常用参数：

| 参数 | 含义 |
|------|------|
| `--sample N` | 每个源抽测 N 个（线路 / 频道名），默认 10；与 `--full` 并存时 **`--full` 优先** |
| `--full` | 全量：测该源全部可测线路，以及频道口径下全部频道名；默认 `workers=24`，并默认开 `--deep`；每源完成打印进度，Ctrl+C 可中断（有 `--json-out` 会尽量落盘） |
| `--deep` | 更深「真能看」：响应若是 m3u8，解析第一条媒体分片或子播放列表并再请求；子列表再跟一层到分片；分片用 TS/fMP4/视频流特征判定，HTML/403/超时算挂。不加时行为与旧版兼容（拿到 m3u8 列表即过） |
| `--phone` / `--strict` | 贴近手机门槛预设：开 deep；`--min-pass` / `--min-pass-channel` 默认 **0.7**；**推荐源要求线路口径与频道口径都达标**（AND，不是 OR）；默认 `--max-lines 1`（只试该频道排序后的第一条，更贴近播放器常先试第一条） |
| `--channel-first-line` | 频道口径只试第一条线路（等价 `--max-lines 1`） |
| `--workers` | 并发数（默认 16；`--full` 时默认 24） |
| `--timeout` | 单请求超时秒数，默认 8（deep 跟进同样沿用） |
| `--min-pass` / `--min-pass-channel` | 线路 / 频道口径门槛（默认 0.5；`--phone` 下 0.7） |
| `--max-lines` | 频道口径每条频道最多试几条线路（默认 4；`--phone` 下 1） |
| `--force-ipv6` / `--vod` / `--json-out` | 强制测 IPv6、顺带测点播、完整结果落盘 |

判定「能播」的口径（默认）：HTTP 成功且响应像 m3u8 播放列表 / TS 切片 / 视频流
（看 `Content-Type` 和内容特征），HTML 错误页、403/404、超时、连不上都算挂。
加 `--deep`（或 `--full` / `--phone` 默认带上）后还会**跟进 m3u8 到分片**再判，更接近「手机点开真能看」。
**退出码 0 = 通过，1 = 有问题**（JSON 坏了、地址重复、推荐源没达标、一条都没通过），
适合推之前跑一遍或挂 CI；被跳过的源不计入失败。

全量可能跑很久（大源 2000+ 频道 × deep 跟分片）；日常推送用 `--sample`，清单大改或用户要求贴近手机时立刻跑 `--full --phone`（不必等周一）。

### 2026-11-06 测法审计：不再把「能下载」当「好用」

```bash
python3 scripts/check_sources.py --vod --vod-sample 8 --vod-playable --timeout 12
python3 scripts/check_sources.py --live --full --phone --timeout 8 --workers 16
python3 scripts/check_sources.py --live --sample 20 --phone --ffprobe  # 有 ffprobe 时真读流
python3 scripts/test_check_sources.py                              # 误判回归夹具
```

- **点播结构**：完整响应、记录真实重定向、显式 gzip/deflate 解压；严格 JSON（兼容整行注释/尾逗号）、JS 变量/JSONP 外壳（只取 JSON，不执行）、`8位标记** + Base64`、JPEG/PNG/GIF/BMP 外壳及 App 同款 AES-CBC（调用本机 `openssl`）。空 `sites`、坏 JSON、只有 `spider` 字段、HTML、未知加密不再靠「出现 sites 字样」放行。多仓只报告，不自动算单仓可用。
- **点播质量**：主/站点级 spider（含 `./` 相对 URL）必须可下载且为可读 jar/ZIP、包含 `classes.dex`，声明了 MD5 就核对；均匀抽测 CMS `列表→详情→首条播放地址`，分别报告列表成功和「媒体迹象」。jar 失效或 CMS 列表通过不足 50% 会报错。`--vod-playable` 的媒体失败单列，不能把本来有详情的站抹成「空列表」。
- **直播内容**：`--phone` 保持全量双口径 ≥70%，跟到分片（最多三层）；支持 M3U/TXT 的 UA/Referer/Origin/Cookie 后缀和 M3U 头，TS 要至少 3 个同步包、MP4/fMP4 看正确 box 偏移，**不能仅凭 `Content-Type: video/*` 或一个 0x47 通过**。频道口径复用同 URL 实测证据，避免第一轮通过、第二轮限流导致假 0%。
- **可选 ffprobe**：`--ffprobe` 对媒体 URL 再识别真实音/视频轨。这仍只证明取样时读到了流，不等于全天不卡、直播内容正确或所有分片都活着。

**仍有局限**：CSP jar 的格式可检不等于 App 内每个爬虫的搜索/播放可用；动态 Cookie、登录/授权码、防盗链私有算法、未知加密格式不绕过，需真机人工复核。抽样媒体、首分片及 ffprobe 不能测长期卡顿、持续追片、片源更新速度、VIP 解析成功率；单网络/单时段结果不能代表所有运营商，IPv6 无出口时只测域名线路。公开清单发现成人/会自动混入成人的源直接排除；仅名称关键词是提示，不替代人工看站构成。

### 两个口径：线路 vs 频道

`--live` 会同时给两个口径，因为**多线路聚合源**（同一个频道名挂 2~6 条备用线路，
比如 `港澳台综合`、`备用1 完整版`）用单条线路口径会严重低估：

- **线路口径**：抽 `--sample` 个（或 `--full` 时全部）播放地址逐个探。只有一条线路的源看它就行。
- **频道口径**：抽 `--sample` 个（或 `--full` 时全部）**频道名**，每个最多试 `--max-lines` 条线路，**有一条能播就算这个频道可用**。
  只有平均线路数 ≥ 1.2 的源才真跑这一轮；单线路源两个口径等价，不会多花请求。
  `--phone` 默认 `max-lines=1`，只认排序后的第一条（更贴近播放器）。

**默认达标规则：两个口径有一个到门槛就算通过**（都不到才算挂）。
**`--phone` 下推荐源（以及报告里的 ✓/✗）要求两个口径都过**——更严，更贴近「列表里点开要稳」。
否则多线路聚合源用 OR 才能进推荐位。报告里多线路源会多打一行：

```
  ✓ 港澳台综合   频道 2334 · 抽测 20 · 可播  8 · 通过率  40% · 26.7s
        多线路源：604 个频道名平均 3.9 条线路；频道口径抽测 20 个，可用 15（75%）
```

同一条源 40%（线路）和 75%（频道）都对：前者说「单条线路的成活率」，后者说「用户点开这个台能不能看」。
**写清单 remark 时两个数都写上**，只写一个会误导。

### IPv6 体检

跑 `--live` 时会先体检一次：先看本机有没有全球 IPv6 地址（只有 `fe80::` 就是没配），
再真连一把双栈站点（解析 AAAA → TCP 连 443）——只有**能连出去**才算有 IPv6 出口，
IPv4 映射地址（`::ffff:1.2.3.4`）会被识破，不会误报。

没有 IPv6 出口时，**只剔除 IPv6 裸地址（`http://[2409:...]`）那些频道**，剩下的域名/IPv4 频道照测
（很多带「IPv6」名头的源里混着不少域名线路，整条跳过会把能播的也丢掉）；
只有整条源全是 IPv6 裸地址时才打 `⊘` 整条跳过——既不进通过名单，也不拉低结论。
想不加区分地全测一遍加 `--force-ipv6`。报告里的剔除/跳过是「本机测不了」，不代表源本身有问题。

## 清单格式

```json
{
  "version": 1,
  "vod": [
    { "name": "我的线路A", "url": "https://example.com/a.json", "remark": "自建", "recommended": true },
    { "name": "备用1", "url": "https://example.net/a.json", "remark": "同源备用域名", "backup": "我的线路A" }
  ],
  "live": [
    { "name": "我的直播", "url": "https://example.com/live.m3u", "remark": "" }
  ]
}
```

- `vod` 是点播配置（单仓 / 多仓 JSON 地址都行），`live` 是直播源（`txt` / `m3u` 地址）。
- 两个数组**可以只写一个**，另一个当作空。
- 每项 `url` **必填**（没地址的条目会被 App 跳过）；`name` 可留空（界面上退回显示地址）；`remark` 可选。
- `version` 目前 App 只当作普通字段忽略，留着方便以后做「清单有更新就提醒」。
- `recommended: true`（可选）标推荐位：App 的「内置源」列表里这些条目**排在最前面**，名字前多一段
  「推荐 · 」，备注跟在后面的括号里（例：`内置 · 推荐 · 饭太硬（主地址，Punycode 已验证）`）。
  没写就是普通条目。排序在 App 侧做，所以清单里不按推荐顺序写也不会乱。
- `backup: "主条目名"`（可选）标**同源备用**：这条必须是那个主地址的**同一份配置的另一个地址**
  （换个域名或路径），不是另一个资源。约定：
  - 备用不写 `recommended`（它是给主地址兜底的，不该自己占推荐位）；
  - 清单里放在**主条目的下一条**（App 会按“资源”分块排序，主条目是推荐位时备用跟着一起排到前面，
    两者永远挨在一起，不会被拆到列表两头）；
  - App 里显示成 `内置 · 备用 · 饭太硬 · 备用1（同源备用域名 fty.xxooo.cf）`。
  - **别把「同一个项目的另一个输出」当 `backup`**。比如 Guovin 的 `ipv4.m3u`（398 频道）和
    `result.m3u`（1180 频道）是两份不同的资源，只能各自当独立条目（跟 `小盒子` / `小盒子 4K` 一样）。
    误标成 `backup` 的后果：App 会把它当「同源副本」排到主条目旁边、显示成 `备用 ·`，但内容其实不一样，
    而且主条目一旦换掉它也跟着跑偏。`备用1 完整版` 就踩过这个坑，已改正。
- 地址里别带空格、换行、制表符：App 会清洗，但清洗过就和你在别处记的地址对不上了。
- 同一份清单里**不要重复**地址。

## 换源时的建议

- 只改 `builtin.json` 一个文件，别改文件名/分支（App 里内置的那条地址是
  `https://gh-proxy.com/https://raw.githubusercontent.com/sukai616/tv-source/master/builtin.json`；换分支就同步改设置里的清单地址）。
- 仓库里的地址尽量用**免登录、无防盗链**的直链。网盘分享页（阿里云盘 / 夸克 / 百度网盘分享）App 直接 GET 拿不到。
- GitHub raw 国内不稳，用 `gh-proxy.com/`、`ghfast.top/` 这类加速前缀包一层（清单里已有例子）。
- 仓库被举报会封：重要的清单建议在对象存储（阿里云 OSS / 腾讯云 COS）再放一份，App 里换清单地址即可。
